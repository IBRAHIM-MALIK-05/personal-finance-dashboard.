# Personal Finance & Budget Dashboard (HCI Project 05)

A web prototype that helps students and households understand their spending, plan bills and savings, and see where
their money is heading. Every number can explain itself, with its formula, inputs and assumptions. Financial
coaches see the same screens in more detail, without a second product.

**Stack:** Python 3 · Flask · Jinja2 · SQLAlchemy Core · **MySQL 8** (administered in MySQL Workbench) · SVG charts
generated by our own Python code · plain CSS and a little vanilla JavaScript · pytest.
All data is **synthetic**. The app never connects to a bank, never asks for bank credentials and gives no investment advice.

---

## 1. Setup (Windows)

1. **Create the database (once).** Open MySQL Workbench, connect as `root`, open
   [`source/db/setup_mysql.sql`](source/db/setup_mysql.sql), replace `CHANGE_ME` with a password you choose, and run it.
   This creates the schemas `hci_finance` and `hci_finance_test` and a user `hci_app`.
2. **Configure the app.** Copy `source/.env.example` to `source/.env` and put the same password in both URLs.
   `.env` is git-ignored.
3. **Install:**
   ```powershell
   cd source
   python -m venv .venv
   .venv\Scripts\pip install -r requirements.txt
   ```

Without a `.env` the app still runs, using a local SQLite file, and every page shows which storage is in use.

## 2. Run

```powershell
cd source
.venv\Scripts\python app.py            # open http://127.0.0.1:5000
.venv\Scripts\python app.py --reset    # reload the original synthetic demo data
```

On first run the tables are created and about 650 synthetic transactions are loaded. Choose a demo profile:

| Profile | Role | Can |
|---|---|---|
| Ayesha | Personal owner (student) | Edit her own budget |
| Bilal Khan, Sana Khan | Household managers (two editors) | Edit the shared household budget; manage coach sharing |
| Coach Sara | Financial coach | **Read-only**, only what the household shares (summary or full); leave notes |

Profiles are demo personas, not real logins. Permissions are still enforced on the server for every read and write.

## 3. Test

```powershell
cd source
.venv\Scripts\python -m pytest            # about 150 tests
```

* Engine, import, validation and graphics tests need no database.
* Service and web tests run on throw-away SQLite files.
* `tests/test_mysql_integration.py` runs the critical paths on **MySQL**: atomic import + undo, version conflicts,
  permissions, InnoDB/utf8mb4 and Unicode round-trip. It runs only when `TEST_DATABASE_URL` is set, and is otherwise
  reported as *skipped*.
* `tests/test_codex_contracts.py` holds independent acceptance tests written from the specification.

## 5. What is simulated

* **All data** is synthetic and generated by `finance/seed.py`. Merchants and people are fictional.
* **Coach sharing** happens between demo profiles inside the app; nothing is sent anywhere.
* **Storage failure** can be simulated from Settings → Storage, to demonstrate the recovery path.
* **Demo profiles** are not authentication. A real deployment would need accounts, passwords or SSO, HTTPS and audited authorisation.

## 6. Known limitations

* Urdu covers navigation and key labels only (a foundation for Constraint Card D4). The Urdu text needs review by a native speaker.
* Undo is built for imports (the whole import, with a partial option). General undo/redo for other actions is not built
  (it would be needed for Constraint Card E4); the Activity log records every change.
* The forecast assumes recurring items happen on schedule and everyday spending follows your recent median month.
  It is a guide, not a prediction.
* Recurring bills are entered by hand. Payments that only look like a bill are shown as suggestions until confirmed.
* There is no offline mode or multi-device sync (Constraint Card E1 is not built).

## 7. Evaluation materials

[`docs/EVALUATION.md`](docs/EVALUATION.md) holds the workbook for personas, scenarios, the 8 usability tasks, consent,
SUS, heuristic review, accessibility audit, findings/retest, Hurdle Log and Break-it responses. **All result fields are
intentionally blank**: they must be filled from real sessions with real participants.

## 8. Tools and libraries

Flask, Jinja2, Werkzeug (BSD-3), SQLAlchemy (MIT), PyMySQL (MIT), cryptography (Apache-2.0/BSD), pytest (MIT),
MySQL Server 8 and MySQL Workbench 8 CE. No chart library is used: all charts are SVG generated by `finance/graphics/`.
No external fonts, images or CDNs.
