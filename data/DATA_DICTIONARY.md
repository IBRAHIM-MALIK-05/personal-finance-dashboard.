# Data dictionary

All data is **synthetic**, generated by `source/finance/seed.py` (seed 2026). Regenerate it with
`python source/scripts/generate_data.py --as-of YYYY-MM-DD`. The same seed and date always give identical files.

| File | Contents |
|---|---|
| `sample_transactions.csv` | Every seeded transaction (654: one student and one household, 6 months) |
| `sample_data.json` | Profiles, workspaces, recurring bills, budgets, goals, contributions, scenarios, counts |
| `messy_import.csv` | Bank-style export for the Week 12 change request (see below) |

## Conventions

* **Money**: signed integer **paisa** (1 rupee = 100 paisa). Inflow (income, refund) is positive; outflow (purchase, bill, transfer out) is negative.
* **Dates**: `DATE` / ISO `YYYY-MM-DD`. Financial events are dates, not times.
* **Currency**: PKR, one currency per workspace.

## Main tables (MySQL schema `hci_finance`; full DDL in `source/db/schema.sql`)

### transactions
| Column | Type | Meaning |
|---|---|---|
| id | INT PK | |
| workspace_id | INT FK → workspaces | Which budget it belongs to |
| posted_on | DATE | Date the money moved |
| amount | BIGINT | Signed paisa, never 0 |
| payee | VARCHAR(80) | Who was paid / who paid |
| description | VARCHAR(160) | Statement text (sanitised) |
| category_id | VARCHAR(32) FK → categories | |
| category_source | VARCHAR(8) | `rule` (automatic), `user` (chosen by hand, never overwritten by rules), `import` (from the file) |
| kind | VARCHAR(10) | `normal`, `refund` (reduces spending in its category), `transfer` (excluded from income/spending) |
| recurring_id, occurrence_date | INT, DATE | Explicit link to a bill occurrence. Only this marks a bill as paid |
| refund_of | INT | The original purchase, when matched |
| import_batch_id | INT | Import that created it (for undo) |
| raw_row, source_mapping | TEXT | Original CSV values and the column mapping used |
| version | INT | Optimistic-concurrency counter, +1 on every edit |

### recurring_bills
`name`, `payee`, `category_id`, `amount` (signed paisa), `cadence` (weekly/monthly/quarterly/yearly), `anchor_date`
(later dates derive from it; day 31 falls on the month's last day), `tolerance_pct` (how much a real payment may differ,
e.g. 50 for electricity), `active`, `version`.

### budgets
`workspace_id` + `category_id` (unique), `monthly_limit` (paisa > 0), `version`.

### goals / goal_contributions
Goal: `name`, `target`, `deadline`, `monthly_plan`. Contribution: `amount`, `on_date`, optional `transfer_txn_id`.
A contribution is an allocation unless a transfer transaction is recorded.

### import_batches / import_journal / import_drafts
A draft holds the uploaded text and the person's choices until commit. A batch records the result and its summary,
including every skipped row with its original values. The journal holds one row per inserted, deleted or restored
transaction, with a before-image for undo and redo.

### profiles / workspaces / memberships / sharing_grants
Demo personas and their access. A coach's access comes only from an unrevoked `sharing_grants` row with scope `summary` or `full`.

### Others
`categories` (16 fixed, with Urdu names), `rules` (system and user keyword rules), `scenarios` (what-if adjustments
as JSON), `coach_notes`, `preferences` (lens, theme, language, motion, horizon), `audit_log`, `meta`.

## messy_import.csv

Header `Txn Date, Narration, Amount (PKR), Category`. **Spending is positive and credits/refunds are negative.** It contains:
mixed date formats (ISO, DD/MM/YYYY, "3 Nov 2026", and two MM/DD rows), ambiguous dates, 4 exact duplicates of
existing transactions, 1 near-duplicate (date shifted), 2 repeated rows, 3 negative refunds/credits, 7 malformed rows
(more than 10%: impossible date, "yesterday", "abc", empty amount, empty description, a stray comma, `1e5`), a
`<script>` tag, emoji, an over-long description, and one future-dated row.
